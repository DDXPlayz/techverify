 DEFINITION: STEM Racing™ India Car
ID: DEF-T1.1
Name: STEM Racing™ India Car Definition
Description: A car designed and manufactured according to these regulations for participation in races on the STEM Racing™ India track at the National Finals event, powered only by a single 8-gram power unit cartridge. STEM Racing™ India cars are designed to travel the 20-metre race and withstand the physical deceleration required after crossing the finishing line.
Category: General
Requirement Type: Boolean
Numerical Values: None
Geometry Needed: Verification that assembly consists only of listed components
Can be checked automatically: PARTIALLY
Automatic Checking Method: Component count verification, material identification, assembly structure validation
Required Inputs: Full car assembly mesh, component classification data
Expected Output: Pass/Fail
Visual Highlight: Highlight any unauthorized components
Engineering Importance: Critical
Notes: Assembly must only consist of: Body, Power Unit Cartridge Chamber, Wheels (x4), Wheel Support Systems (x4), Tether Line Guides (x2), Nose Cone, Front Wing(s), Front Wing Support Structure, Front Wing End Plates, Rear Wing(s), Rear Wing Support Structure, Surface Finishes and Decals, STEM Racing™ India Logo Decal, Halo, Helmet. Adhesives with no dimensional impact are permissible for joining components.

 PART 14: SUGGESTED SOFTWARE ARCHITECTURE

 Browser-Based Geometry Engine Architecture

 1. Core Geometry Engine
Components:
- Three.js/Mesh Processing: 3D model loading, manipulation, and visualization
- CSG (Constructive Solid Geometry): Boolean operations for volume analysis
- CAD Kernel Integration: For precise geometric calculations

Functions:
- Mesh loading and parsing (STL, OBJ, STEP formats)
- Coordinate system establishment (track surface, reference planes)
- Bounding box calculations
- Distance measurements between points, surfaces, and edges
- Angle measurements
- Volume calculations
- Surface area calculations
- Minimum thickness analysis
- Ray casting for visibility checks

 2. Rule Processing Module
Functions:
- Rule database management
- Rule classification (GENERAL, SAFETY, PERFORMANCE)
- Sequential rule processing
- Dependency management (some rules depend on others)
- Error handling and reporting

 3. Measurement Extractor
Functions:
- Extract all required measurements from 3D model
- Generate measurement values for each property
- Validate measurement precision
- Store measurement results

 4. Compliance Checker
Functions:
- Compare measurements against regulation limits
- Apply absolute and proportional penalties
- Generate compliance report
- Highlight violations

 5. Visualization Engine
Functions:
- 3D model rendering with measurement overlays
- Color-coding for compliance status:
  - Green: Compliant
  - Yellow: Warning/Close to limit
  - Red: Non-compliant
- Measurement arrows and annotations
- Reference plane visualization
- Highlighting of specific regions (virtual cargo, safety zones)

 6. Report Generator
Functions:
- Generate detailed compliance report
- List all measurements with values and limits
- Show penalty calculations
- Provide visual evidence of violations
- Export HTML/PDF reports

 7. User Interface
Functions:
- Upload 3D model
- Select car to analyze
- View 3D model with annotations
- Navigate through violations
- View detailed measurements
- Export reports

 8. API Layer
Functions:
- REST API for external integration
- Model upload endpoints
- Rule processing endpoints
- Report generation endpoints

 9. Data Storage
Functions:
- Store car models
- Store measurement results
- Store compliance history
- Store rule definitions

 10. Integration Points
Functions:
- CAD software export (Fusion 360, SolidWorks)
- Engineering drawing analysis (PDF, CAD formats)
- Weight scale integration (API)
- Competition management system integration

 Implementation Considerations

 Measurement Accuracy
- Use double-precision floating point calculations
- Implement tolerance handling for edge cases
- Support for measurement units (mm, g, °)

 Performance Optimization
- LOD (Level of Detail) for complex meshes
- Parallel processing for independent measurements
- Caching of measurement results

 Security
- Secure model upload and storage
- Access control for competition officials
- Audit trail for compliance checks

 Browser Compatibility
- WebGL support for 3D rendering
- Progressive Web App (PWA) capabilities
- Mobile-friendly interface

 Extensibility
- Plugin architecture for custom rules
- API for adding new measurement types
- Rule versioning and updates

 Testing
- Automated test suite for all rules
- Test models representing edge cases
- Regression testing for rule updates

 Example Workflow
1. Model Upload: User uploads car model (STL/OBJ)
2. Model Processing: System loads and validates model
3. Reference Establishment: System identifies reference planes and track surface
4. Measurement Extraction: System extracts all required measurements
5. Compliance Checking: System checks each rule against measurements
6. Penalty Calculation: System calculates penalties for violations
7. Report Generation: System generates detailed compliance report
8. Visualization: System displays model with violations highlighted
